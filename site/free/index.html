Build your own free translation endpoint

You end withA private URL pasted into Discord Translator
TimeAbout 9 minutes
CostNothing. No card, ever.

This page uses Google Apps Script, which runs inside the Google account you already have. That is the whole of what Discord Translator needs: the plugin’s two paid providers were removed, so there is no key to buy and no billing account to open.

What you are actually deploying

Three plain facts about this design. None of them is a reason not to do it; all three are reasons to keep your URL to yourself.

  • The endpoint is deployed as Anyone. That is the only setting the plugin can reach, and it means the URL on its own is enough to call it — no Google sign-in stands in front of it.
  • The script runs as your Google account, spending your Apps Script quota. It cannot read your mail or your files: it only calls the translation service.
  • So the deployment URL is the credential. There is no password behind it: the roughly 57 random characters in the URL are the whole of it, and anyone holding them can spend your daily quota.

Deploy as Anyone, and treat the URL like a password. That is the whole security model. Nothing can be charged — Apps Script has no billing attached — so the worst a leaked URL costs you is a day of translations, and the quota resets.

Nothing on this path costs money. There is no Cloud project, no billing account, no credit card and no quota page. You are using the Apps Script allowance that comes with an ordinary Google account.

Why not just use Cloud Translation? Because it stops you at a billing wall

Cloud Translation refuses to run without a billing account attached. The dialog is explicit: Billing required — Cloud Translation API requires a project with a billing account. There is no way past it without a card.

Apps Script has no such wall. Same company, same translation engine underneath, different product, different rules.

It is not a choice this plugin still offers, either: Discord Translator’s two paid providers were removed, and there is no field left to paste a Cloud key into. This page is the path.

What this does not give you
  • No SLA. Apps Script is a consumer service. If it is slow, it is slow.
  • A daily ceiling you cannot raise. 5,000 translate calls a day on a gmail.com account. Past that it stops until the quota rolls over.
  • Cold starts. The first call after a quiet period can take a second or two longer.
  • Your account, your quota. Sharing the URL shares your allowance, and every call is attributed to you.

What you are copying — the whole script

Thirty-odd lines, and this is all of them. It accepts a POST, checks the shape of it, calls Google’s translation service, and returns JSON. It reads nothing and it writes nothing.

// Discord Translator - free translation proxy.
// Runs in YOUR Google account, on YOUR Apps Script quota.
// No Cloud project, no billing account, no credit card.
//
// THE DEPLOYMENT URL IS THE CREDENTIAL. TREAT IT LIKE A PASSWORD.
// This is deployed as "Anyone", so no sign-in stands in front of it: whoever
// holds the URL can call it and spend your daily translation quota. Nothing can
// be charged, because Apps Script has no billing, and the quota resets daily.

function doPost(e) {
  var body, texts, target, source, out;
  try {
    body = JSON.parse(e.postData.contents);
  } catch (err) {
    return json({ error: 'body was not valid JSON' });
  }
  texts = body.q;
  target = body.target;
  source = body.source || '';
  if (!Array.isArray(texts) || !target) {
    return json({ error: 'expected { q: ["text"], target: "en" }' });
  }
  try {
    out = texts.map(function (t) {
      return LanguageApp.translate(t, source, target);
    });
  } catch (err) {
    return json({ error: 'translation failed' });
  }
  return json({ translations: out });
}

function json(obj) {
  return ContentService
    .createTextOutput(JSON.stringify(obj))
    .setMimeType(ContentService.MimeType.JSON);
}
  • doPost is the name Apps Script looks for when something POSTs to your web app URL. Rename it and nothing answers.
  • There is no password in this file. The deployment URL is the credential, and the only one — whoever you give it to can spend your daily quota.
  • LanguageApp.translate(text, source, target) does the translating. An empty source string means auto-detect.
  • ContentService returns the reply as JSON rather than as a web page.
  • Both catch blocks return a flat message instead of Google’s raw error, which can carry internals.

You do not need to copy this text anywhere. Taking the copy above brings the entire project across, formatting and all. It is here so you can read what you are about to run.

A popup may appear first, saying which account you are signed in as

On first open you may get a small dialog reading “You’re currently signed in as” followed by your email address, with two buttons: Change account and OK.

The account it names is the one that will own the script, run it, and spend the quota. If that is the account you want, dismiss it with OK.

Leave “Execute as” on Me

About 1 minute

The Configuration column now shows a Description box and two dropdowns. Check the first one, Execute as, reads Me followed by your email address. It already does. Leave it.

Underneath it, verbatim:

“The web app will be authorised to run using your account data.”

The Description box is free text with a New description placeholder. It is for you, and it can stay empty. Something like discord translator v1 helps if you ever redeploy.

What “Execute as Me” is actually granting

Every call runs under your identity and spends your Apps Script quota, whoever made the call. That is exactly what you want here — it is why the plugin does not need a Google account of its own.

The script can only do what its code does. This one calls LanguageApp.translate and nothing else: it never touches Gmail, Drive or Calendar, so if Google ever does ask you to authorise anything, it can only be the scopes the code actually uses.

There is also an info strip in this column reading “This can also be used as a library.” Ignore it. It is not relevant to what you are building.

4

Set “Who has access” to Anyone

About 1 minute — the one step everybody gets wrong

Open the Who has access dropdown and change it from its default. It contains exactly three options, in this order:

  1. Only myself — the default. Wrong.
  2. Anyone with a Google Account — looks right. Also wrong.
  3. Anyone — this one. Pick it.

Look at the dropdown again before you leave this step and confirm it reads exactly Anyone.

Leave it on “Only myself” and the URL will exist and do nothing useful

The deployment succeeds. You get a URL. Open it in your browser and it may even look fine, because you are signed in.

The plugin is not. It receives a Google sign-in page — HTML, where it expected JSON — and reports a parsing failure. That reads like a broken script, so people go back and rewrite working code. It is a permissions setting.

“Anyone with a Google Account” is not “Anyone”

They sit next to each other in the same short dropdown and read almost identically. The difference is the whole step.

Discord Translator cannot sign in to Google. It sends an HTTP request and nothing else. So an endpoint that requires any Google sign-in is an endpoint the plugin cannot use, however valid the account.

Only the bare word Anyone works.

This is also why the URL matters: with Anyone, the URL alone reaches the script, and nothing else stands in front of it. The URL is the credential. Keep it to yourself, and the next section replaces it if it ever gets out.

Press Deploy and copy the Deployment ID

About 2 minutes

Press Deploy. The dialog goes straight to a success panel — in the deployment this page was written from, nothing appeared in between.

The success panel reads “Deployment successfully updated.” and shows three things:

  • Version 1 and the date. If you have deployed this project before, it will be the next number up instead.
  • Deployment ID — a long code with its own Copy button. This is the one to take. It is the same code that sits in the middle of the Web app URL, so the plugin can rebuild the whole address from it.
  • Web app URL — starts https://script.google.com/macros/s/ and ends in /exec, with its own Copy button. This works too. If you already have it, or you are on a Google Workspace account, paste this one instead — a Workspace address carries your organisation’s domain, which cannot be rebuilt from the ID alone.

Press the Copy button on the Deployment ID row, then press Done. What you copied should be one long run of letters, digits, hyphens and underscores with no slashes in it. If it starts with https:// you pressed the Copy button on the Web app URL row instead — that is fine, the plugin accepts either.

If Google asks you to authorise the script instead — a branch this guide did NOT observe

Not observed. In the run this page was written from, pressing Deploy went straight to the success panel: no authorisation prompt, no consent screen, no interstitial. Paste it into Discord Translator

About 1 minute

Two settings, both inside Discord:

  1. In Settings → Plugins → ChannelTranslator → the cog, set the translation provider to Google Apps Script (your own free proxy).
  2. In Settings → Discord Translator, find the Apps Script proxy section, paste the Deployment ID you copied in step 5, and press Save. That box takes either form — the ID or the whole Web app URL — and expands an ID into the full URL for you. Save also tries it for real against your own deployment, so a bad paste is caught here rather than at your first message.

The plugin cog has a box for the same value, and it takes either form too — both boxes ask the same question of the same checker. Whichever one you fill in, the other shows what you saved.

Then translate one message. A reply comes back in a second or two.

The two forms look like this. Yours will have a different AKfycb… portion, and that portion is the credential — do not paste it anywhere public.

Checking it by hand before you trust it

A correct endpoint answers a POST with JSON and nothing else:

{"translations":["hola"]}

Two answers that mean something specific:

  • A short JSON error message — the endpoint is reachable and running your script; the body you sent was the wrong shape. Good news: steps 1 to 6 worked.
  • Anything starting with <!DOCTYPE html> — you received a sign-in page. Step 4 was not applied. Go back to it.

What you get a day, and how that compares

Google publishes these limits for Apps Script. The consumer column is what a gmail.com account gets.

Apps Script quotas, from Google’s quota documentation. Google changes these; their page is the authority.
LimitConsumer accountWorkspace account
Translate calls5,000 / day20,000 / day
URL Fetch calls20,000 / day100,000 / day
Script runtime6 min / execution6 min / execution

The one that binds is translate calls: 5,000 a day. The 6-minute runtime never matters here, because a translation returns in well under a second.

The honest comparison. Cloud Translation has no free tier — it has a monthly credit of up to USD 10, which covers roughly 500,000 characters a month. At an average message of 120 characters that is about 138 messages a day before you start paying USD 20.00 per 1,000,000 characters.

This path gives you 5,000 translations a day, and past that it stops rather than bills. More generous, and free, with no card on file to be charged.

What this path gives up in exchange
  • No SLA and no support. Cloud Translation is a paid product with commitments behind it. This is not.
  • A ceiling you cannot buy your way past. 5,000 a day is the limit for a consumer account, full stop.
  • Slightly slower. There is an extra hop through Apps Script, and the first call after a quiet period is slower still.
  • You are the operator. When it breaks, you are the one who fixes it.

For one person translating a Discord server, those are cheap trade-offs. There is no paid tier behind this plugin to move up to, so they are the trade you are making.

When the daily count resets

Apps Script quotas run on a daily cycle and roll over on their own. The exact reset moment is not something this page verified, and Google’s documentation is the authority. In practice: if you hit the ceiling, you are waiting hours, not days.

You cannot raise this limit, and there is no page to raise it on. That is the trade for paying nothing.

Replacing the URL, and shutting it down

Do this if the URL has been shared, pasted into a chat, committed to a repository, or was on a machine you no longer trust. The URL is the credential, so a leaked URL is a leaked password, and the only way to take it back is to stop it answering.

Replace the URL — about 3 minutes

  1. Deploy → Manage deployments → select the old deployment → Archive or Delete, whichever the menu offers. The old URL stops answering immediately.
  2. Deploy → New deployment, and walk steps 3 to 6 again. Check that Who has access reads Anyone once more — a fresh deployment does not inherit it.
  3. Put the new URL into Discord Translator, over the old one.
Open Apps Script ↗

A new deployment always means a new URL. Here that is the point rather than a nuisance: the old string is the thing that leaked, and archiving it is what makes it worthless.

Editing the script is not deploying it. Apps Script serves the version you deployed, not what sits in the editor. To push a code change, use Deploy → Manage deployments → edit the deployment (pencil) → Version: New version → Deploy. That route keeps the same URL — which is exactly why it is no use when the URL is the thing you are trying to retire.

Delete the deployment — about 1 minute

The complete stop. Deploy → Manage deployments → select the deployment → Archive or Delete, whichever the menu offers. The URL stops answering immediately.

Deploying again afterwards produces a new URL, so you will re-do step 6.

Deleting the whole project instead

From the Apps Script project list, remove the project itself. That takes every deployment with it and is the strongest stop available on this path.

You lose the script, so keep a copy of your edited version first if you intend to come back.

Where your URL is stored on your machine

It lives in Discord Translator’s settings. In the browser extension that is discord.com storage, readable by any script running on that page; the desktop build keeps settings in its own data directory instead.

The worst case here is bounded in a way a Cloud key is not: a stranger with the URL can spend your daily translations. Nobody can charge your card, because there is no card.

If you want a shared secret as well

It buys very little on this path. The URL and the secret would sit in the same settings store and travel in the same request, so anyone able to steal one has already stolen both. An earlier version of this guide shipped a placeholder secret, which was worse than none at all: every copy started with the same value, printed here for anyone to read.

If you want one anyway, add two pieces to your copy of the script — a constant, and a check as the first thing after the JSON.parse block:

const SHARED_SECRET = 'pick-your-own-long-random-value';

// inside doPost, immediately after the JSON.parse try/catch:
if (body.secret !== SHARED_SECRET) {
  return json({ error: 'unauthorised' });
}

Deploy a New version afterwards, and send secret alongside q and target on every request. Discord Translator has no field for a secret and never sends one, so the plugin will stop working against that endpoint: this is for people calling the URL from their own code.

Do one more thing

Open your Web app URL in a private browsing window, where you are not signed in to Google. If you took the Deployment ID in step 5 rather than the URL, the address is https://script.google.com/macros/s/ followed by that ID and then /exec — which is exactly what the plugin builds for you. Anything that is not a Google sign-in page is correct — it proves the plugin can reach it. A Google sign-in page means step 4 did not take, and you would otherwise find that out from a failure that looks like broken code.
