## 3. What the review caught that I would have shipped

### The one that mattered

**PRIVACY.md stated, in bold, that the browser extension never contacts `api.github.com`. That was
false.** The Changelog tab was registered in the web bundle with no updater guard, and it fetches a
commit range from GitHub.

My evidence for the claim was a recorded extension session showing only `discord.com` and
`translate.googleapis.com`. That evidence **could not have found it**:

```
changelogManager.ts:396
  if (!lastSeenHash || lastSeenHash === "unknown" || lastSeenHash === gitHash) return;
```

The request fires only once a previous version has been seen — the *second* version a user runs.
Every recording I took was a fresh profile, which is precisely the case where it stays silent. This
is the wrong-layer measurement failure in its purest form: a true observation, of the wrong thing,
supporting an absolute claim.

Fixed two ways, because the tab being unreachable is weaker than the code being absent:

1. The tab is gated `!IS_UPDATER_DISABLED &&`, exactly like the Updater tab above it.
2. `fetchCommitsBetween` refuses on `IS_UPDATER_DISABLED` before touching the network, so esbuild
   folds the body away.

Verified against the built files, with the desktop build as the positive control:

| | browser bundle | desktop bundle |
|---|---|---|
| `compare/` URL construction | **absent** | present |
| `vnd.github+json` header | **absent** | present |

The desktop column is what makes this evidence rather than a hope — it shows the removal is
build-conditional and not a blanket deletion. One unreferenced string constant survives; PRIVACY.md
now says so.

### A test that could vanish silently

`vitest.config.ts` globs `test/**/*.test.ts`. Deleting `test/allowedHosts.test.ts` would leave the
suite green with 11 files instead of 12, and the control PRIVACY.md describes would be gone with
nothing saying so. `release.yml` now names it explicitly. Negative-controlled: file moved away →
exit 1, `No test files found`; file restored → exit 0, 40 passed.

### Packaging defects, all found by reading artifacts rather than sources

| Defect | Consequence |
|---|---|
| `buildExtension` called `rm("chromium-unpacked")` while writing to `dist/browser/chromium-unpacked` | The output directory was **never cleaned**, so files removed from the package kept shipping |
| The zip step was fire-and-forget — nothing awaited `Zip.zip` | The process could exit before writing and publish the **previous build**. It had already shipped a Firefox archive containing a tree removed from the package |
| 1.5 MB vendored Monaco tree packaged that nothing in the browser build loads | **86% of the download**. Packages went 1.78 MB → 248 KB |
| 8 inherited keyboard shortcuts with no consumer in the bundle | Listed in the browser shortcut UI, did nothing |
| Firefox manifest declared optional `authenticationInfo` + `locationInfo` | A data-collection consent surface for data nothing here collects |

The first two are the serious pair: together they mean a local build could publish stale bytes.

## 7. Residual hazards

| Severity | Hazard |
|---|---|
| **HIGH** | **The QuickCSS editor loads Monaco from `cdn.jsdelivr.net` into a page whose CSP this extension strips.** The loader and stylesheet are SRI-pinned; the modules the loader then fetches are not. A bad jsdelivr publish would run in the logged-in `discord.com` origin. The fix needs monacoWin.html served from an extension URL — attempted and reverted, see the previous turn report. |
| **MEDIUM** | `scripts/checkHosts.mjs` enumerates hosts only in the two asars. The extension zips are checked by `checkExtensionPackages.mjs`, which does not enumerate hosts. PRIVACY.md now states this limit rather than implying full coverage. |
| **MEDIUM** | The Firefox package is unsigned, so it installs only as a temporary add-on and does not survive a restart. Documented in the README and the release notes. |
| **LOW** | Neither extension is in a store. Chrome Web Store review would likely flag the `Discord` trademark in the extension name. |
| **LOW** | The desktop `native.ts` still does not re-check the host after a redirect; the browser transport does. Back-port pending. |
