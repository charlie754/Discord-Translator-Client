# Hosts allowed to appear in dist/desktop.asar and dist/equibop.asar.
#
# scripts/checkHosts.mjs enumerates every host present in the packed archives
# and fails CI on anything not listed here. Adding a line is a deliberate
# decision to ship one more third party the user's client can be pointed at —
# it is not housekeeping. Justify it in the PR that adds it.
#
# Removing code that reaches a host? Remove its line too, or the next audit
# reads a stale list as the current attack surface.
#
# Derived by running `node scripts/checkHosts.mjs` against the STANDALONE build
# (`pnpm build --standalone`, which is what release.yml now publishes) at
# dist/desktop.asar sha256 f840f6912c4a910ad5f28651c0a8a9ae98e254bebd9d62b59bc3d2f2d4e42932
# and dist/equibop.asar sha256 1076a606f047fcbf1217a158e7b635e69bf6c961479eec51a26ac50cd4f411e2
# — that is, from what actually ships, not from what src/main/csp/index.ts says.
# That run reported: OK: 55 entries, all listed in scripts/allowed-hosts.txt.
#
# Build the same way before regenerating this list. A non-standalone build ships
# the git updater instead of the http one, so it enumerates a different set: it
# omits the two .asar filenames below and it is not the artifact users install.
#
# The archives carry a vendored Monaco tree (monaco/vs/**), whose dotted
# identifiers — TextMate scope names like `variable.php`, settings keys like
# `workbench.hover.delay` — are shaped like hostnames. checkHosts.mjs suppresses
# its bare-hostname pass under vendored paths for exactly that reason (see
# isVendoredPath), which is why ~491 such tokens do not appear below. Its URL
# pass still runs over that tree and is authoritative; the four real hosts it
# finds there are listed under the Monaco heading below.
#
# The section headings below are context for reviewers. The checker does not
# read them: every uncommented line is simply an allowed entry.

# The two DeepL API hosts, reached only by
# src/plugins/channelTranslator/core/providers/deepl.ts. Neither is contacted with the
# shipped defaults: the provider setting is "google", and the registry refuses to construct
# DeepL at all until the user pastes a key of their own (resolveProvider() in
# core/providers/registry.ts). They exist so that a gtx rate limit is inconvenient rather
# than terminal. DeepL splits its API by plan and a key is valid on one host only — free
# keys end in ":fx" and route to api-free, everything else to api — so both are needed.
# Both also appear in the ALLOWED_HOSTS set in native.ts; a host declared in one place and
# not the other is either a dead provider or an undeclared third party.
