#
# scripts/checkHosts.mjs enumerates every host present in the packed archives
# and fails CI on anything not listed here. Adding a line is a deliberate
# decision to ship one more third party the user's client can be pointed at —
# it is not housekeeping. Justify it in the PR that adds it.
#
# Removing code that reaches a host? Remove its line too, or the next audit
# reads a stale list as the current attack surface.
#
# Derived by running `node scripts/checkHosts.mjs` against the STANDALONE build
# (`pnpm build --standalone`, which is what release.yml now publishes) at
# dist/desktop.asar sha256 f840f6912c4a910ad5f28651c0a8a9ae98e254bebd9d62b59bc3d2f2d4e42932
# and dist/equibop.asar sha256 1076a606f047fcbf1217a158e7b635e69bf6c961479eec51a26ac50cd4f411e2
# — that is, from what actually ships, not from what src/main/csp/index.ts says.
# That run reported: OK: 55 entries, all listed in scripts/allowed-hosts.txt.
#
# Build the same way before regenerating this list. A non-standalone build ships
# the git updater instead of the http one, so it enumerates a different set: it
# omits the two .asar filenames below and it is not the artifact users install.
#
# The archives carry a vendored Monaco tree (monaco/vs/**), whose dotted
# identifiers — TextMate scope names like `variable.php`, settings keys like
# `workbench.hover.delay` — are shaped like hostnames. checkHosts.mjs suppresses
# its bare-hostname pass under vendored paths for exactly that reason (see
# isVendoredPath), which is why ~491 such tokens do not appear below. Its URL
# pass still runs over that tree and is authoritative; the four real hosts it
# finds there are listed under the Monaco heading below.
#
# The section headings below are context for reviewers. The checker does not
# read them: every uncommented line is simply an allowed entry.
#
# The two paid providers were removed outright - Google Cloud Translation v2 and
# DeepL - together with the API-key settings, the spend meter and the monthly cap
# that existed only to bound their bills. Nothing shipped can charge a user any
# more. Their three lines are gone with the code that reached them, and the host
# names are deliberately NOT written out anywhere in this file: a grep for one of
# them across the repo should return nothing, and a comment naming them would make
# that check answer yes on a provider that no longer exists. The enumeration
# stamped above therefore predates their removal as well as the additions noted
# below - it is a record of the run it names, not a current count.

# Google Apps Script, reached only by
# src/plugins/channelTranslator/core/providers/appsScript.ts. NOT a third party in the sense
# translate.googleapis.com above is: what is contacted is a Web App the USER deployed into their OWN
# Google account, at a URL only they hold, running a script they pasted. There is no API key and no
# billing - Apps Script has none - so the ceiling (about 5,000 calls a day on a consumer account)
# refuses rather than charges. Not contacted with the shipped defaults: the provider setting is
# "google", and the registry refuses to construct this provider at all until the user pastes their
# own deployment URL (resolveProvider() in core/providers/registry.ts).
#
# What this line grants that the gtx line does not: script.google.com hosts EVERY Apps Script
# deployment on the internet, so an exact-host match cannot distinguish the user's own proxy from
# anyone else's. The path is what does that, and the path is not enforced here - it is enforced by
# checkDeploymentUrl() in appsScript.ts, which accepts only /macros/s/<id>/exec (or the Workspace
# /a/macros/<domain>/s/<id>/exec) and REBUILDS the URL from the parsed host and path, dropping any
# query, fragment or embedded credentials the paste carried. Added after the enumeration stamped in
# the header above, so that run's count predates this line.
#
# Also in the ALLOWED_HOSTS set of all three transports (native.ts, browser/translationHost.js,
# browser/translationBridge.ts) and in the host permissions of both browser manifests; a host
# declared in one place and not the other is either a dead provider or an undeclared third party.
# It was a dead provider until this line existed: apps-script shipped selectable and unreachable.
script.google.com
# Where Apps Script SERVES THE RESULT of a Web App call, and the only reason this line exists.
#
# A POST to https://script.google.com/macros/s/<id>/exec does not answer with the translation. It
# answers 302, and the JSON is served from this host - measured against a live deployment: with
# redirect following on, the request lands on script.googleusercontent.com and returns
# {"translations":[...]}; with redirect: "manual" the same call returns 302 and nothing else. So
# script.google.com alone is a provider that cannot complete a single request.
#
# It is only ever reached as the TARGET OF THAT 302 from script.google.com. Nothing in the plugin
# builds a URL on this host: checkDeploymentUrl() in core/providers/appsScript.ts accepts only a
# script.google.com deployment URL, so the sole way a request arrives here is the redirect branch
# in the three transports - which reads the Location, puts it through the same checkUrl() the
# original URL went through, and reissues ONE bodiless GET. A 307 or 308 is still refused outright,
# because those replay the POST body and this host would then receive the user's message text.
#
# What the line grants that script.google.com does not: this host serves USER CONTENT for every
# Apps Script deployment on the internet, on a sandbox domain shared with other Google user
# content. As with script.google.com the exact-host match cannot distinguish the user's own
# deployment from anyone else's, and here not even the path helps - the /macros/echo path carries
# an opaque user_content_key. What limits the exposure is that the response is only ever read
# after a 302 from an allow-listed host, and that nothing is ever POSTed here.
#
# Also in the ALLOWED_HOSTS set of all three transports and in the host permissions of both
# browser manifests. Added after the enumeration stamped in the header above, so that run's count
# predates this line.
script.googleusercontent.com
